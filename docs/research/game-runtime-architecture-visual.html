日记络络独立版总体架构

方向：Electrobun 桌面壳 + 新宿主前端 + Host Adapter + Node 引擎进程 + lolocard/JS-Slash-Runner 内容与运行时复用。

分层结构

1. Desktop Shell
Electrobun 窗口与打包
本地存档目录 / 配置目录
启动、退出、窗口控制
2. Game Frontend Shell
主菜单：继续 / 新游戏 / 加载 / 设置 / 退出
常驻 galgame 主界面，不再以酒馆楼层为主
底部命令：Q.save / Q.load / save / load / log / setting / hide
3. Host Adapter
变量 / 世界书 / 事件 / 资源路径接口
消息时间线 / log / save-load / investigation context
双模型路由：故事模型 + 逻辑模型
4. Engine Process
Node 子进程承载 SillyTavern 能力层
provider 接入 / prompt 转换 / 角色卡处理
不复用 ST 原宿主 UI，只复用能力
5. Content Runtime
lolocard 的日记络络内容、世界书、第一条消息
JS-Slash-Runner 的可移植 runtime 与工具函数
素材、galgame 样式、选择框和地图玩法

一次游戏操作的数据流

1
玩家操作

点击继续、空格推进，或打开互动 / 移动 / 调查。

2
宿主前端解释动作

把 UI 操作转成统一 Action，例如推进剧情、提交对话、切换地点、临时调查。

3
Adapter 组装上下文

读取当前变量、世界书、地图位置、短期调查上下文、log 和存档状态。

4
双模型执行

逻辑模型先更新变量和状态，故事模型再输出最终文本与界面标签。

5
结果结构化

生成场景更新、角色表现、可见文本、选项、地图变化、log 项和存档快照差异。

6
前端持续呈现

界面始终停留在 galgame 样式，不再把 galgame 塞进某个聊天楼层。

产品内要替换掉的旧模型

旧：酒馆楼层历史 新：剧情时间线 + 独立 log 系统。
旧：AI 回复某条楼层才显示 galgame 新：游戏界面始终就是 galgame 宿主。
旧：消息即全部历史 新：正式 log、短期调查上下文、场景状态分离存储。
旧：单一模型心智 新：故事模型负责叙事，逻辑模型负责变量与判定。
